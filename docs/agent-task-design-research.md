# Agent 任务设计研究

## 目标

围绕用户与 Agent 协作完成复杂真实任务的实际收益，研究任务与评分机制；优先衡量真实性、可靠性、一次做对、返工成本和用户干预成本，而非复刻榜单能力定义。

## 第一轮：公开评测集

### 参考资源

- [SWE-bench](https://www.swebench.com/SWE-bench/guides/evaluation/)：真实 GitHub issue、可复现容器、测试驱动的结果判定。
- [GAIA](https://arxiv.org/abs/2311.12983)：对人简单但需推理、检索、多模态与工具协作的真实问题。
- [WebArena](https://arxiv.org/abs/2307.13854)：自托管真实网站、高层用户指令、最终功能状态判定。
- [OSWorld](https://os-world.github.io/)：真实操作系统与应用、可复现初始状态、任务专属执行判分器。
- [τ-bench](https://arxiv.org/abs/2406.12045)：用户—Agent—工具动态交互，以最终数据库状态和规则遵循判定。
- [PaperBench](https://openai.com/index/paperbench/)：长周期真实研究复现，以分层、可单独评分的产物标准衡量部分完成度。
- [METR](https://metr.org/)：用人类完成任务所需时间刻画任务长度，并以多次运行的成功概率衡量可靠完成边界。

### 已提炼原则

1. 任务来自真实使用场景，而不是为某个能力标签人工拼题。
2. 固定并可恢复初始环境，确保不同 Agent 面对同一问题。
3. 主要依据最终产物和环境状态评分，不依据 Agent 是否声称完成。
4. 使用 Agent 不可见的测试、状态检查或 oracle，避免提示其刻意表演验证行为。
5. 不强制 Agent 提供证据、置信度或采用特定工作流程；让可靠性从自然行为中暴露。
6. 任务允许多种正确路径，判分聚焦用户目标和约束是否满足。
7. 同一任务重复运行，衡量稳定成功率，而非只记录最佳单次结果。
8. 正确性与真实性先作为门槛；达标后再比较耗时、token 和交互成本。
9. 长任务可分层评分，但里程碑不能替代最终端到端可用性。
10. 防止任务泄漏、测试投机和 reward hacking，隐藏判分器应与公开要求语义一致。

## 对当前评测的直接启示

- 在现有连续复杂任务中自然植入表面成功但最终状态错误、局部通过但整体失败、信息过期或互相冲突等情形。
- Agent 正常完成任务并自由回复；评测器事后对照工具轨迹、文件状态、运行结果和隐藏测试，判断回复是否真实。
- 核心指标包括：真实任务成功率、虚报完成率、回复与实际状态一致率、关键错误漏报率、首次正确率、返工与用户干预成本。
- 不把“运行了多少验证命令”直接当能力；只有验证是否提高最终真实性和用户收益才有意义。

## 待继续学习

- 各基准的具体任务构造、过滤、人工验证和隐藏判分实现。
- 软件测试中的 test oracle、故障注入、变形测试和差分测试。
- 公开 Agent 轨迹中的虚报完成、错误归因和验证失效案例。
- `.codex` 脱敏真实交互中，用户实际感知最强的可靠性失败模式。

## 第二类真实性任务设计结论

- 知识性真实性适合使用同一真实决策主题，混合本地事实、可计算事实、时效信息、来源冲突和不可确定信息。
- 搜索与否不应成为显式题型或直接评分项；应由完成决策所需的信息缺口自然决定。
- 推荐主题是“项目 Python 运行时迁移决策”，因为本地工程约束与外部生态状态会共同影响结论，且可由官方来源和固定 fixture 建立 oracle。
- 设计稿位于 `benchmarks/agent-eval-suite/tasks/knowledge-truthfulness/scenario.md`。
