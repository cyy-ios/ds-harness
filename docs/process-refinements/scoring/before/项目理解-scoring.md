# 优化前项目理解评分规则摘要

本文件是优化前“项目理解”评分规则的可读摘要，只用于历史对比，不参与当前评分。当前规则见 `benchmarks/agent-eval-suite/rubrics/项目理解-scoring.md`。

## 优化前设计

项目理解分为两个维度：

1. 初始主动理解：首轮是否主动探索项目、理解目标、识别子项目、判断完成度和项目类型。
2. 动态更新：后续轮次是否跟踪当前环节、识别主线/支线、识别废弃方向、区分完成/研究中、隔离无关任务。

## 主要问题

### 1. 口头表达占比过高

旧规则会检查 response 是否说明项目目的、子项目、完成度和项目类型。很多 agent 实际读了文件并正确行动，但没有在 response 里复述，导致被低估。

### 2. 边界词主观

“大部分”“明显错位”“轻微偏差”等描述不够稳定，不同评分 session 可能给出不同档位。

### 3. 与其他能力重叠

项目理解、用户意图理解、任务规划之间存在重叠，尤其是“对话流位置”“策略匹配”和“主线/支线识别”。

## 后续优化方向

优化后保留“首轮探索”和“动态更新”两层结构，但把判断依据尽量改为可观察行为：

- 首轮是否读取入口文档和关键目录。
- 后续是否沿用前轮产物，而不是重复推倒重来。
- 遇到支线/中断后是否回到主线。
- 是否盲信 memory、handoff、compact summary 中的过期状态。
