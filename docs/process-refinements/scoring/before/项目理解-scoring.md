# 项目理解

维度 1（初始主动理解）和维度 2（动态更新）独立评分，各 100 分。

**维度汇总**：维度1 仅首轮评分，非首轮 N/A；维度2 非首轮每轮结合当前及前序所有轮证据评分后取均值。最终得分 = 维度1×w1 + 维度2均值×w2，w1/w2 见 `capability-weights.yaml` 的 sub_dimension_weights。

### 维度1：初始主动理解（100分）

#### 1.1 主动探索（25分）

证据：首轮的 `replay.jsonl`。

100：Read 了至少一个项目级 md 文件（如 README、CLAUDE.md、或 docs 下 md），且 Glob 或 Grep 了至少一个目录。
75：Read 了项目文档但未做任何目录结构探索。
50：有 Glob 或 Grep 但无任何 Read。
25：首轮无任何文件操作 tool call。
0：操作的文件路径与项目完全无关。

#### 1.2 目的理解（25分）

证据：首轮的 `response.md` + `replay.jsonl`（Read tool_result 中的文件内容）。

评分 agent 提取 response 中关于"项目要解决什么问题""要达成什么效果"的句子，回溯 replay 中 Read 的文件内容，检查是否有原文支撑。

100：response 同时描述了"要解决的问题"和"要达成的效果"，且已读文件内容中有可对应的原文。
75：描述了其中一项且有支撑，另一项未涉及或缺乏支撑。
50：提到了项目名称或大致方向，但未做"要解决什么问题"或"要达成什么效果"的具体描述。
25：response 的声称与已读文件内容存在直接矛盾。
0：response 中无任何项目目的相关内容。

#### 1.3 子项目识别（20分）

证据：首轮的 `response.md` + `replay.jsonl`（Glob/Read 的路径及 tool_result 内容）。

评分 agent 比对 response 中声称的子项目/方向/阶段，与 replay 中探索的目录结构和文件内容是否吻合。

100：response 列出了多个子项目/方向/阶段且说明了关系，在 replay 的 Glob 路径或 Read 内容中有对应。
75：列出了多个方向但关系描述缺失，或与 replay 中可见的目录结构不匹配。
50：只提到了一个方向，但 replay 显示其探索过多个子目录。
0：response 中提到的子项目在 replay 中无对应探索记录，或完全未提及子项目结构。

#### 1.4 核心文件（15分）

证据：首轮的 `replay.jsonl`（Read 的路径列表）。

100：Read 覆盖了项目入口文档，且深入到至少一个子目录内的代码或配置文件。
75：Read 了入口文档和部分子目录文件，但未触及代码文件（.py/.rs/.ts/.js 等）。
50：只 Read 了顶级文件，未进入任何子目录。
0：未 Read 任何文件内容。

#### 1.5 完成度判断（10分）

证据：首轮的 `response.md` + `replay.jsonl`（Read tool_result 中的文件内容）。

评分 agent 比对 response 中的完成度声称与 replay 中已读进度类文档的内容。

100：response 明确区分了"已完成""进行中""未开始"（或等效表述），且 replay 中有含进度信息的文档被 Read。
75：有完成度描述但只有模糊的整体判断，未逐项区分。
50：response 提到了进度，但 replay 中无任何含进度信息的文档被 Read。
0：response 中完全没有涉及完成度。

#### 1.6 项目类型（5分）

证据：首轮的 `response.md`。

100：首轮 response 中有项目类型判断（如聚合型/分散型/单线项目）。
0：无类型判断。

### 维度2：动态更新（100分）

#### 2.1 环节追踪（25分）

证据：所有轮的 `prompt.json` + `response.md`。

按轮顺序检查 agent 对"现在在做什么"的表述是否连贯递进，是否与对应 prompt 匹配。

100：每轮 response 反映了对应 prompt 的环节要求，且表述比上一轮有递进，无认知倒退。
75：大部分轮次有递进，但个别轮次停留在上一轮认知。
50：多数轮次仅当 prompt 明确告知环节时才跟上，无主动认知。
25：至少一次 response 与对应 prompt 要求明显错位。
0：各轮 response 相互独立，无进度累积感。

#### 2.2 主/支线识别（25分）

证据：所有轮的 `prompt.json` + `response.md` + `replay.jsonl`。

评分 agent 先通读所有 prompt 确定主线 topic，再找出偏离 prompt，检查偏离轮的处理深度是否较主线明显收敛，以及偏离后是否回归。

100：偏离轮的 response 和 tool call 数明显少于主线轮，且偏离后正确回归主线。
75：能区分但处理深度未明显收敛（偏离轮的量与主线轮接近）。
50：偶尔区分但多数轮主支线处理深度无差异。
0：偏离后主线丢失，后续 response 再也回不到主线。

#### 2.3 废弃方向识别（20分）

证据：所有轮的 `replay.jsonl`（Read tool_result 内容）+ `response.md` + `prompt.json`。

当 replay 中已读文件包含"旧版""已废弃""草稿""[legacy]""[deprecated]"等标记，或 prompt 中告知方向变更时，检查 response 是否对此有反应。

100：response 明确提到了方向变化、旧方向及废弃原因、新方向，且可追溯到 replay 中的废弃标记或 prompt 中的变更告知。
75：提到了变化但原因或保留部分的分析与已读文档内容不一致。
50：只模糊说"之前有些变化"无具体说明，但已读了废弃标记文档。
0：已读废弃标记文档或已收到变更告知，但 response 中无任何反应，仍按废弃方向推进。

#### 2.4 完成/研究中区分（15分）

证据：所有轮的 `replay.jsonl`（Read tool_result 内容）+ `response.md`。

检查 agent 对已确定内容（"完成""已确定""最终"等标记）和未确定内容（"研究中""草稿""待定"等标记）是否采用不同处理方式。

100：对已确定内容不提出推翻性建议、不做重复修改；对未确定内容留审慎措辞。
75：大致区分但偶有对已完成内容的无效重讨论。
50：需要在 prompt 中多次被告知"已完成"后才区分。
0：无区分意识，对已完成内容反复推倒重来。

#### 2.5 无关任务隔离（15分）

证据：所有轮的 `prompt.json` + `response.md` + `diff.patch`。

当 prompt 请求与主线无关，检查完成该请求后主线的清洁度。

100：完成无关请求后，后续 response 无该请求的引用残留，diff 中无相关文件变更。
75：后续有零星无关话题提及或少量相关文件残留。
50：把无关请求当主线处理，扩大了处理范围。
0：后续所有轮围绕无关任务展开，原主线丢失。
