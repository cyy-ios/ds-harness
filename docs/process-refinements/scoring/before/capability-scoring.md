# 优化前通用能力评分规则摘要

本文件是优化前评分规则的可读摘要，只用于历史对比，不参与当前评分。当前评分规则见 `benchmarks/agent-eval-suite/rubrics/`。

## 优化前结构

能力权重大致为：

- 真实性可靠性：20%
- 指令遵循：15%
- 任务完成度：15%
- 项目理解：10%
- 用户意图理解：10%
- 任务规划：10%
- 结果预期：10%
- 异常分析能力：10%

## 主要能力定义

### 用户意图理解

关注 agent 是否识别请求针对的项目、目的、workspace 归属、对话流位置和处理策略。

问题：大量子项依赖 response 是否主动描述“我理解了什么”，对不爱复述的高效 agent 不公平。

### 结果预期

关注最终产物是否可消费、是否完整执行、自检是否充分。

问题：旧规则容易把 agent 自称“已验证”当成正信号，证据坐标要求不够强。

### 任务规划

关注路线效率和工具选择。

问题：对“绕路”“明显”“大部分”等边界描述主观，跨 session 给分漂移大。

### 任务完成度

关注是否完成 prompt 要求、是否覆盖核心子步骤、是否保持已有功能。

问题：容易和 acceptance 分数混用，需要拆开“任务是否做成”和“声称是否真实”。

### 异常分析能力

关注遇到错误时是否定位、分析、修复、验证。

问题：旧规则使用“大致正确但不到位”等描述，缺少可执行判据。

### 指令遵循

关注持久规则和单轮指令是否被遵守。

问题：需要把持久规则、单轮指令、产品 harness 行为区分开，不能把工具/权限差异都算到模型身上。

### 真实性可靠性

关注 response 声称与实际 replay、diff、artifact、acceptance 是否一致。

问题：旧规则虽然方向正确，但缺少逐条 claim 对齐和 deduction 闭合要求。

## 被替换原因

旧规则可读性强，但不够可复查。优化后把评分要求改成：逐轮、逐子项、证据坐标、deductions 闭合。
