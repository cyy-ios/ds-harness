# 评分机制优化总结（2026-06-19 ~ 2026-06-20）

## 优化前的问题

**问题 1：评分 Agent 偷懒**。一套评分覆盖 8 个能力 × ~4 子项 × ~7 轮 = ~224 个独立分数，塞在一个评分 pass 里。认知负载过大，Agent 走捷径——不逐子项逐轮打分，凭整体印象给大概分。

**问题 2：同一 Agent 在不同 session 给分不一致**。评分细则里大量使用"大部分""轻微""明显""严重"等主观模糊词，不同 session 的 LLM 对这些词理解不同，导致同一证据在不同 session 得分不同。

**问题 3：大量评分子项依赖 Agent 口头表述**。比如"agent 是否在 response 里说了项目要解决什么问题""agent 是否体现了对对话流位置的判断"。高效 Agent 不会主动说这些废话，不说就被扣分，不合理。

## 优化内容

### 1. 防偷懒：拆分评分流程 + 完整性自检

改 `scoring-output.md`：引入预校准机制——步骤 0 一次性盲打全部 8 个能力，与参考分逐项对比校准，通过则作为最终分无需重打。评完后强制执行完整性自检：逐一检查每个 score.json 的子项覆盖、轮次覆盖、null 合理性、deductions 闭合。任一不通过必须回头补。

同步更新 `orchestrator.md` 评分步骤。

### 2. 量化模糊边界：清单式评分替换五档主观判分

将所有子项的评分从自然语言五档描述改为可机械判定的清单式/占比式/二分式评分。改动覆盖 `capability-scoring.md` 和 `项目理解-scoring.md`。

原则：评分 Agent 不再需要"理解"和"判断"，只需执行字符串匹配、计数、路径比对。

**典型改动举例**：

- **项目理解 1.1/1.4 合并为"首轮探索深度"**（原两档五级 → 三个布尔检查项，达成几个给几档分）
- **项目理解 2.1"环节追踪"**：从"response 有没有说自己在递进"改为看 replay——产物接续、无冗余回退、操作递进三项
- **项目理解 2.2"主/支线识别"**：从"明显少于""正确回归"改为偏离比 ≤50% + 关键词回归检查
- **任务规划 1.1"路线效率"**：从"轻微/明显/严重绕路"改为有效 step 占比（≥80%=75，≥50%=50…）
- **用户意图理解 1.4**：从"response 是否体现位置判断"改为 prompt 关键词比对 + replay 行为匹配表
- **异常分析能力**：从"分析大致正确但不到位"的四档主观判分改为 4 阶段顺序检查（定位→分析→修复→验证），每阶段二值判定，证据锚 replay.jsonl + response.md + diff.patch。不用 acceptance.json，避免与任务完成度共用证据源
- **真实性 1.1**：从不准确程度主观判断改为逐条计数比对，不准确比例 × 标注率交叉定档（百分比矩阵）

**统一"关键词重合度"定义**：从 prompt 中提取长度 ≥2 的非停用词计数，重合度 = 交集/基准轮总数。消除不同 session 提取关键词的歧义。

### 3. 去掉口头依赖：口头子项零权重或改行为

这些子项依赖 Agent 在 response 里主动说出来：

| 文件 | 子项 | 做法 |
|------|------|------|
| 项目理解 | 1.2 目的理解 | 权重→0 |
| 项目理解 | 1.3 子项目识别 | 权重→0 |
| 项目理解 | 1.5 完成度判断 | 权重→0 |
| 项目理解 | 1.6 项目类型 | 权重→0 |
| 用户意图理解 | 1.2 目的理解 | 权重→0 |
| 项目理解 | 2.1 环节追踪 | 改行为 |
| 用户意图理解 | 1.4 对话流位置 | 改行为并合并 1.5 |
