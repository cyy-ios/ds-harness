# 评分设计原则

每新建/修改一个评分子项，按以下顺序执行。每完成一步再进下一步。

## 1. 定锚点

打开 evidence 目录，列出该能力能用的证据文件。每条规则必须锚到 replay.jsonl / commands.log / diff.patch / acceptance.json 中可数的值。

禁止锚到 response.md 的"理解""意图""体现""判断"等主观表述。response.md 仅用于真实性核对和指令格式检查。

写完问：这个判断查的是哪个文件的哪个字段？

## 2. 选判定

量化类（测多少/多完整）：比例 > 计数 > 语义描述
例：不准确率≤10% 优于 ≤2条 优于 "大部分准确"

定性类（测是不是/有没有）：关键词/字符串匹配 > 语义判断
例：response 含"AttributeError" 优于 "分析了错误根因"

档位边界必须是数字。禁用"小幅""明显""基本""大致"。

写完问：换一个 LLM 查同一个字段，会不会得出不同结论？

## 3. 查重查漏

查重：这个子项和其他子项测了同一个维度？测了就合并或砍掉。
查漏：拿表现好、差各一个极端轮次，能不能打出不同分？打不出 = 无区分力。
查边界：分母=0、文件数=1、diff为空、gate_passed不存在时会不会崩？

## 4. 对标旧规则（仅修改已有规则时）

翻旧规则原文，逐档对比：旧规则能分开的场景，新规则分不开 → 补档或补维度。旧规则每档描述里隐含的区分角度，新规则必须有对应覆盖。

## 自检

□ 锚在 replay/diff/commands/acceptance 哪个字段？
□ 换一个 LLM 打分，结果一样吗？
□ 好中差三档都能落到不同分吗？
□ 和其他子项重叠吗？
□ 极端值/小分母/空值崩了吗？
□ 旧规则能分开的，新规则还能分开吗？（仅修改时）

≥3 个不确定 → 回到步骤 1。
